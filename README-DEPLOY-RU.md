# GlamAI Studio — AI-помощник визажиста

Веб-приложение для превью макияжа на фото клиента: загрузите портрет, соберите образ
на палитре (8 продуктов, оттенки, интенсивность, финиш) или загрузите референсное фото —
и ИИ перенесет макияж на ваше фото, сохранив лицо. Есть слайдер «до/после».

- **Next.js 16** (App Router) + TypeScript + Tailwind 4
- AI: `z-ai-web-dev-sdk` (генерация/редактирование изображений + vision-модель glm-4.6v)
- Интерфейс на русском, тёмная тема «графит + золото», адаптив под мобильные

---

## 1. Что делать с файлами проекта

Скачанный архив (`glamai-studio.zip`) — это исходный код сайта. Сначала распакуйте его:
правый клик по архиву → **«Извлечь всё…»** (Windows умеет это сам) или 7-Zip / WinRAR.

Дальше два пути:

- **Путь А — публикация в интернете (рекомендуется).** Ничего устанавливать не нужно:
  только браузер. Смотрите раздел 2.
- **Путь Б — запуск на своём компьютере.** Понадобится установить Node.js.
  Смотрите раздел 3.

## 2. Публикация на Vercel (рекомендуемый путь)

### Шаг 1. Загрузите код на GitHub — прямо из браузера

1. Откройте https://github.com и войдите (или зарегистрируйтесь — бесплатно)
2. Нажмите **«+»** (правый верхний угол) → **New repository**
3. Имя: `glamai-studio` → выберите **Private** → **Create repository**
4. На открывшейся странице нажмите ссылку **«uploading an existing file»**
   (или кнопка **Add file → Upload files**)
5. Перетащите в окно **всё содержимое распакованной папки** (папки `src`, `public`,
   `prisma` и все файлы рядом с ними) и нажмите **Commit changes**

Загрузка через командную строку git — альтернатива для тех, кто им пользуется:

```bash
git init
git add .
git commit -m "GlamAI Studio"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/glamai-studio.git
git push -u origin main
```

### Шаг 2. Получите API-ключ Z.AI

В превью-песочнице доступ к AI уже настроен, но для работы на Vercel нужен
**свой ключ** платформы Z.AI:

1. Зарегистрируйтесь на https://z.ai/model-api
2. Создайте Standard API Key: https://z.ai/manage-apikey/apikey-list
3. При необходимости пополните баланс: https://z.ai/manage-apikey/billing

### Шаг 3. Импортируйте проект в Vercel

1. https://vercel.com → войдите через GitHub → **Add New → Project** → выберите репозиторий
2. Framework определится сам (Next.js), ничего менять не нужно
3. В разделе **Environment Variables** добавьте две переменные:

   | Имя           | Значение                        |
   |---------------|---------------------------------|
   | `ZAI_API_KEY` | ваш ключ из шага 2              |
   | `ZAI_BASE_URL`| `https://api.z.ai/api/paas/v4`  |

4. Нажмите **Deploy** — сборка займёт 1–2 минуты

Готово: приложение будет доступно по адресу `https://имя-проекта.vercel.app`.

### Как это работает под капотом

SDK читает конфиг доступа только из файла `.z-ai-config`, которого на Vercel нет.
Поэтому роут `/api/tryon` перед вызовом ИИ вызывает `ensureZaiConfig()`
(файл `src/lib/zai-config.ts`): он собирает `.z-ai-config` из переменных
окружения `ZAI_API_KEY` и `ZAI_BASE_URL`. Файл пишется в папку проекта
(работает и локально на Windows), а если это невозможно (Vercel — read-only) —
во временную папку. Ключ не попадает в git и в браузер: `.env` и
`.z-ai-config` внесены в `.gitignore`.

## 2а. Движок Яндекс вместо Z.AI — оплата в рублях (версия 1.4.0)

Если оплата Z.AI в долларах неудобна, приложение может работать на
**Yandex Cloud AI Studio**: YandexGPT понимает фото и текст, YandexART рисует
портрет с макияжем. Оплата — в рублях из платёжного аккаунта Yandex Cloud
(карты «Мир», СБП, Сбер и т.д.). Новым пользователям обычно начисляется
пробный грант — часть генераций получится бесплатно.

**Ничего в коде менять не нужно.** Достаточно задать две переменные —
приложение само переключится на Яндекс (переменные Z.AI_* можно не трогать
и не удалять: они просто перестанут использоваться).

### Шаг А. Ключ и каталог Yandex Cloud

1. Войдите на https://console.yandex.cloud (это тот же Яндекс-аккаунт, где у вас уже есть ключ)
2. Запишите **ID каталога (folder id)**: консоль → слева «Каталоги» (или откройте каталог — id виден в адресной строке и в карточке)
3. Слева выберите **«Сервисные аккаунты»** → создайте (или откройте свой) →
   назначьте ему ДВЕ роли:
   - `ai.languageModels.user` — текст и понимание фотографий (YandexGPT)
   - `ai.imageGeneration.user` — генерация картинок (YandexART)
4. В карточке сервисного аккаунта: **«Создать новый ключ» → API-ключ** —
   скопируйте строку (вид `AQVN…`) сразу: она показывается один раз

### Шаг Б. Переменные в Vercel

Settings → Environment Variables → добавьте:

| Имя            | Значение                                     |
|----------------|----------------------------------------------|
| `YC_API_KEY`   | API-ключ сервисного аккаунта (AQVN…)         |
| `YC_FOLDER_ID` | ID каталога из шага А                        |

Затем **Redeploy** (Deployments → ⋯ → Redeploy) — без него переменные не
подхватятся, так же как с Z.AI.

### Шаг В. Проверка

Откройте `https://ваш-сайт.vercel.app/api/health?ping=1` — в ответе должно быть
`"provider": "Яндекс (Yandex Cloud AI Studio)"` и `"ycPing": {"ok": true}`.

### Что важно знать про Яндекс-движок

- **Правки именно вашего фото нет** (как и у публичного Z.AI): YandexGPT
  описывает внешность с фото словами, YandexART рисует новый портрет с
  выбранным макияжем. Лицо может немного отличаться — приложение честно
  помечает такой результат как «портретный режим».
- **Генерация занимает 10–40 секунд** (YandexART рисует асинхронно) — это
  нормально, просто дождитесь результата.
- **Тарифицируется отдельно**: текст/vision — по токенам (копейки за запрос),
  картинка — за изображение. Точные цены: https://aistudio.yandex.ru/ru/docs/ai-studio/pricing
- Если health пишет 403 — не назначены роли из шага А; если «нет средств» —
  не активирован платёжный аккаунт или закончился грант (консоль → Биллинг).

## 3. Запуск на своём компьютере (Windows / Mac)

Понадобится **Node.js версии 20 или новее** — скачайте LTS-установщик
с https://nodejs.org и установите (везде «Далее»).

Затем в папке проекта:

1. Откройте папку проекта в Проводнике → в адресной строке напишите `powershell`
   и нажмите Enter (откроется терминал прямо в этой папке)
2. Выполните две команды:

   ```
   npm install
   npm run dev
   ```

3. Откройте в браузере http://localhost:3000

**Важно про ИИ локально:** без ключа сайт откроется, но кнопка генерации вернёт
ошибку. Чтобы работало: скопируйте файл `.env.example` под именем `.env`,
откройте Блокнотом и впишите свои значения `ZAI_API_KEY` и `ZAI_BASE_URL`
(те же, что в разделе 2, шаг 3), сохраните и перезапустите `npm run dev`.

## 5. Если генерация «отказывает» (диагностика)

### 5.1. Экспресс-проверка — страница самодиагностики

Приложение теперь умеет проверять само себя. Откройте в браузере:

```
https://ваш-адрес-сайта/api/health
```

(локально: `http://localhost:3000/api/health`)

Страница покажет статус каждого пункта:

| Пункт | Что проверяет | Если «не ОК» — что делать |
|---|---|---|
| Переменные окружения | Заданы ли `ZAI_API_KEY` и `ZAI_BASE_URL` | Локально: создайте `.env` по образцу `.env.example` и перезапустите сервер. На Vercel: Settings → Environment Variables → добавьте переменные → **Redeploy** |
| Файл конфига SDK | Сможет ли приложение найти `.z-ai-config` | Появляется автоматически из переменных выше; если нет — значит, переменные не подхватились (перезапустите сервер / сделайте Redeploy) |

Чтобы проверить ещё и **сам ключ** (его принимает ли ИИ-сервис), откройте:

```
https://ваш-адрес-сайта/api/health?ping=1
```

Эта проверка делает один минимальный запрос к ИИ. Если видите «ИИ отвечает. Ключ принят» — конфигурация полностью рабочая, а проблема с генерацией — во времени/лимитах, не в настройках.

Кроме того, при открытии сайта баннер сверху сам предупредит, если ключ ещё не настроен.

### 5.2. Таблица сообщений

Приложение теперь само распознаёт причины отказа и показывает понятное сообщение.
Таблица ниже — что означает каждое из них и что делать.

| Сообщение на экране | Причина | Что делать |
|---|---|---|
| «Ключ доступа к ИИ не найден…» | Нет переменных `ZAI_API_KEY` / `ZAI_BASE_URL` — конфиг SDK не собрался | Локально: создайте `.env` по образцу `.env.example`, перезапустите `npm run dev`. На Vercel: переменные + **Redeploy**. Проверка: `/api/health` |
| «Слишком много запросов к ИИ-сервису подряд. Подождите минуту…» | Лимит обращений к ИИ (ошибка 429). Возникает после 5–8 генераций подряд | Подождите 2–3 минуты и повторите. Приложение уже само сделало 3 повторные попытки с паузами |
| «ИИ-сервис не принял ключ доступа…» | Ключ неверный, отозван или закончился баланс | Проверьте ключ в кабинете Z.AI, затем переменные в Vercel и **Redeploy**. Проверка ключа: `/api/health?ping=1`. Убедитесь, что в ключе есть точка между частями (формат `ID.секрет`) |
| «В ключе доступа к ИИ есть перенос строки или пробел…» | Ключ разорван на две строки при вставке (так бывает, если копировать части ключа по отдельности — консоль показывает их друг под другом) | Пересохраните `ZAI_API_KEY` **одной строкой** (формат `ID.секрет`, точка посередине, без пробелов), затем **Redeploy**. Проверка: `/api/health?ping=1` |
| «ИИ-сервис не успел ответить (таймаут)…» | Сервис ИИ перегружен или сеть | Просто нажмите «Создать образ» ещё раз |
| «На аккаунте Z.AI не хватает средств для генерации изображения…» | Модель картинок тарифицируется отдельно от текста и не входит в подписки (примерно $0.015 за изображение) | Пополните баланс на z.ai в разделе Billing (или подключите пакет ресурсов) и повторите через пару минут |
| «Сервер не успел обработать запрос (таймаут платформы)» | Платформа хостинга закрыла долгий запрос | Повторите попытку; на Vercel не превышайте лимит 60 с Hobby-плана |
| «Фото слишком большое для отправки» | Файл больше 4.5 МБ после сжатия | Сожмите фото (любой онлайн-сжиматель) и загрузите снова |

**Полезно знать:** одна генерация — это 1–4 обращения к ИИ (основная генерация +
QA-проверка результата + при необходимости корректирующий повтор). Поэтому при
активном тестировании лимит обращений расходуется быстро — это нормально, нужна
пауза в пару минут. Если «слишком много запросов» появляется часто, включите
галку **«Быстрый режим — без проверки качества»** под кнопкой генерации: одна
генерация станет одним обращением к ИИ, лимит будет расходоваться в 4 раза
медленнее (но без авто-проверки оттенков и симметрии).

## 6. Частые вопросы

**Ошибка 404 при генерации (статус 404)** — до версии 1.3.0 приложение обращалось к
операции «правка фото», которой нет у публичного API Z.AI (она есть только у
внутреннего шлюза Z.AI). Текстовый ИИ работал, поэтому диагностика была зелёной,
а первая же генерация падала с 404.

С версии 1.3.0 приложение само подбирает рабочий способ:

- **правка фото** (лицо клиента сохраняется) — если сервис её поддерживает;
- **портретный режим** — если правка недоступна: ИИ сначала описывает внешность
  с фото словами, затем модель картинок создаёт фотореалистичный портрет с
  выбранным макияжем. Лицо может немного отличаться от оригинала — результат
  честно помечается жёлтой плашкой «Режим портрета» над сравнением.

Какой режим используется — видно в `/api/health` (поле `imageMode`).

**Генерация возвращает ошибку 401/403** — ключ не подхватился. Проверьте, что
обе переменные (`ZAI_API_KEY`, `ZAI_BASE_URL`) добавлены в Vercel и после их
добавления сделан **Redeploy** (переменные применяются только к новым сборкам).
Также убедитесь, что ключ скопирован целиком одной строкой и содержит точку
между частями (`ID.секрет`): при ручной склейке двух строк точка часто
теряется, и ИИ отвергает такой ключ. Тип ключа — Standard API (не Coding Plan).

С версии 1.2.0 приложение само вычищает из ключа случайные пробелы и переносы
строк, а на ошибки с разорванным ключом отвечает понятной подсказкой.

**Ошибка «ИИ не смог разобрать макияж на референсе»** — на фото слишком сложный
ракурс или плохое освещение. Возьмите более чёткий фронтальный референс.

**Долгая генерация** — норма: 15–25 секунд (в референс-режиме два обращения к ИИ).
Vercel Hobby ограничивает функции 60 секундами; если генерация не успевает,
поднимите `maxDuration` в `src/app/api/tryon/route.ts` на Pro-плане или оставьте
как есть — обычный промпт-режим укладывается в лимит.

**Фото клиентов** — изображения обрабатываются в памяти и никуда не сохраняются:
ни в базу, ни на диск сервера.
